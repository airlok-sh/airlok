# checkup.sh — проверка сервера

Скрипт смотрит на типичные проблемы VPS: вход по SSH, открытые наружу базы, файрвол, обновления, бэкапы, Docker. На выходе отчёт простыми словами: что найдено, чем грозит и что сделать.

## Что скрипт делает и чего не делает

- **Только читает.** Ничего не устанавливает, не меняет настройки и не перезапускает сервисы. Даже `apt update` не запускает, потому что он обновляет кэш пакетов.
- **Не ходит в сеть.** Никуда не отправляет данные, отчёт печатается только у вас в терминале.
- **Не выводит секреты.** Для файлов `.env` проверяются права доступа и имена переменных, но не значения. Ключи, найденные в собранном фронтенде, показываются только первыми символами, SSH-ключи — только отпечатками.
- **Не стучится в сайт снаружи.** Сайт проверяется изнутри: по конфигу nginx, сертификатам и файлам проекта на диске.

Это обычный bash-скрипт на одну страницу, его можно прочитать целиком перед запуском.

## Запуск

Работает на Ubuntu и Debian, на других Linux часть пунктов пропускается.

1. Скопировать `checkup.sh` на сервер, например так:

   ```bash
   scp checkup.sh user@ваш-сервер:~
   ```

2. Запустить на сервере и сохранить отчёт в файл:

   ```bash
   sudo bash checkup.sh | tee checkup-report.txt
   ```

Без `sudo` скрипт тоже работает, но пропускает пункты, которым нужен root (настройки SSH, файрвол, ключи всех пользователей). Пропущенные пункты перечислены в конце отчёта.

## Перед тем как отправить отчёт

В отчёте могут оказаться имена контейнеров и пользователей, пути к файлам, номера открытых портов, отпечатки SSH-ключей (почта в комментарии к ключу маскируется). Паролей и содержимого файлов там нет. Просмотрите отчёт и уберите то, чем не хотите делиться.

## Что проверяется

| Пункт | Как |
| --- | --- |
| Вход по SSH с паролем, вход root | `sshd -T` |
| Базы и кэши, открытые в интернет, Docker API | `ss -tlnp`, `docker ps` |
| Docker публикует порты в обход ufw | `docker ps` + `ufw status` |
| Файрвол | `ufw`, `nft`, `iptables` |
| Защита от перебора | fail2ban, CrowdSec, sshguard |
| Автообновления и неустановленные обновления безопасности | `unattended-upgrades`, `apt list --upgradable`, `/var/run/reboot-required` |
| Контейнеры: privileged, docker.sock, автоперезапуск, ротация логов, root | `docker inspect` |
| Файлы с секретами, доступные всем | права `.env`, `*.pem`, `*.key` |
| Лишние пользователи с root и sudo, ключи SSH | `/etc/passwd`, группы, `authorized_keys` |
| Приложение в режиме разработки (`next dev`, `vite`, `runserver` и т. п.) | список процессов |
| Бэкап базы | cron, systemd-таймеры, файлы дампов |
| Диск, память, swap, падения из-за нехватки памяти | `df`, `/proc/meminfo`, журнал ядра |
| `.env`, `.git`, дампы в публичной папке сайта | каталоги `root` из `nginx -T` с учётом правил `deny` в каждом `server` |
| HTTPS, перенаправление с HTTP, заголовки безопасности, версия nginx | `nginx -T` |
| Срок сертификата, самоподписанный сертификат, автопродление | `openssl`, `/etc/letsencrypt`, таймер certbot |
| Секретные ключи в коде для браузера (OpenAI, Anthropic, Stripe, service_role Supabase и др.) | поиск по `.next/static`, `dist`, `build`, `out` |
| Секреты в переменных `NEXT_PUBLIC_`, `VITE_` и подобных | имена переменных в `.env` |

Отсутствие находки не означает, что сервер в безопасности: скрипт проверяет только перечисленное.
