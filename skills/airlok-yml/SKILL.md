# airlok.yml: подготовить проект к публикации

`airlok.yml` лежит в корне проекта (в монорепозитории — в папке приложения) и говорит Airlok, что проекту нужно: базу,
загрузки, задачи по расписанию и все переменные окружения с описаниями для человека.

Как собрать файл — порядок, поля, пример и что задаёт сам Airlok — отдаёт инструмент MCP `guide` с темой `manifest`.
Вызывай его перед работой: поля и возможности Airlok меняются, и инструкция там всегда актуальная. Если проект хранит
данные в файлах (SQLite, JSON) — ещё и `guide` с темой `data`. Если инструментов Airlok нет, попроси человека один раз
выполнить `npx @airlok/cli setup` и перезапустить агента.

После файла — `npx @airlok/cli check --json`: исправь всё из `errors` и не пропускай `warnings`.

Никогда не выдумывай значения секретов, не подставляй заглушки и не коммить `.env` с настоящими значениями.
